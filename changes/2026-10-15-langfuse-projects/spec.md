# Spec: one Langfuse project for each use case

Intent: [intent.md](intent.md).

## Names

| Name | What it is |
|---|---|
| **project file** | `/opt/model-monitor/langfuse-projects/<use_case_id>.yaml`: the keys of one Langfuse project; the source of truth |
| **routes file** | `otel-collector.routes.yaml`: generated Collector routes and exporters, one per project file |
| **projects env** | `langfuse-projects.generated.env`: generated env form of the keys, for the containers |
| **project tool** | `backend/scripts/langfuse_projects.py`: validates project files, checks keys, generates the routes file and the projects env |
| **`unrouted`** | the project for spans with no known use case (today's `model-monitor`, renamed) |
| **env slug** | the `use_case_id` in upper case with every character that is not `A-Z0-9` replaced by `_` (`rtr-fraud-validation` → `RTR_FRAUD_VALIDATION`) |

## Project file

```yaml
use_case_id: rtr-fraud-validation      # = the Langfuse project name = the file name
public_key: pk-lf-…
secret_key: sk-lf-…
added_at: "2026-10-15T08:00:00Z"
```

Rules (the project tool refuses a file that breaks one, and then writes nothing):
- Unknown fields are refused. `public_key` starts with `pk-lf-`, `secret_key` with `sk-lf-`.
- The file name is `<use_case_id>.yaml`.
- `use_case_id` is `unrouted` or a use case of the registry.
- Two files must not have the same env slug.
- `unrouted.yaml` must exist.

## Generated files

**Routes file** (YAML, generated; header comment "Generated by the project tool from
langfuse-projects/*.yaml; do not edit"). For each project file except `unrouted`, in
registry order:

```yaml
connectors:
  routing/langfuse:
    default_pipelines: [traces/langfuse-unrouted]
    error_mode: ignore
    table:
      - context: span
        condition: >-
          resource.attributes["use.case.id"] == "rtr-fraud-validation"
          or (resource.attributes["use.case.id"] == nil and attributes["use_case_id"] == "rtr-fraud-validation")
          or (resource.attributes["use.case.id"] == nil and attributes["use_case_id"] == nil
              and resource.attributes["service.name"] == "rtr-fraud-validation")
        pipelines: [traces/langfuse-rtr-fraud-validation]
exporters:
  otlphttp/langfuse-rtr-fraud-validation:
    endpoint: http://langfuse-web:3000/api/public/otel
    headers:
      Authorization: "Basic ${env:LANGFUSE_OTLP_AUTH__RTR_FRAUD_VALIDATION}"
      x-langfuse-ingestion-version: "4"
  otlphttp/langfuse-unrouted: { … the same, with LANGFUSE_OTLP_AUTH__UNROUTED }
service:
  pipelines:
    traces/langfuse-rtr-fraud-validation:
      receivers: [routing/langfuse]
      exporters: [otlphttp/langfuse-rtr-fraud-validation]
    traces/langfuse-unrouted:
      receivers: [routing/langfuse]
      exporters: [otlphttp/langfuse-unrouted]
```

The exact field names (`condition` or `statement`) are fixed by the CI test against Collector
0.161.0 (Task "collector-routing"); the plan writes the form that passes it.

**Projects env** (mode 600):

```
LANGFUSE_PROJECTS=unrouted,rtr-fraud-validation
LANGFUSE_PK__UNROUTED=…
LANGFUSE_SK__UNROUTED=…
LANGFUSE_OTLP_AUTH__UNROUTED=<base64 of pk:sk>
LANGFUSE_PK__RTR_FRAUD_VALIDATION=…
…
```

## Collector

- `otel-collector.yaml`: remove `exporters.otlphttp/langfuse`; the `traces` pipeline exports
  to `[debug, file, routing/langfuse]`. The span file and `debug` still get every span.
- Collector command: `--config=/etc/otelcol/config.yaml --config=/etc/otelcol/routes.yaml`;
  the routes file is mounted read-only (local: `otel-collector.routes.local.yaml`; test host:
  `/opt/model-monitor/compose/otel-collector.routes.yaml`).
- Without a routes file the Collector does not start (the component `routing/langfuse` is
  undefined). That is wanted: it never drops spans silently.

## Backend

- **Server span:** in `POST /api/batch/runs`, after the body is valid, the route also sets
  `use_case_id` and `run_id` on the HTTP server span (the parent of `monitor.ingest`).
  Rejected requests (401, 403 before the body, 400, 413) carry no use case and go to `unrouted`.
- **Keys:** `config.langfuse_project_keys() -> dict[str, tuple[str, str]]` from
  `LANGFUSE_PROJECTS` and `LANGFUSE_PK__<slug>` / `LANGFUSE_SK__<slug>`. If `LANGFUSE_PROJECTS`
  is not set, the old `LANGFUSE_PUBLIC_KEY` / `LANGFUSE_SECRET_KEY` count as `unrouted`
  (compatibility for the switch).
- **Evaluator:** the sender takes the evaluation's `use_case_id` and uses its project's keys,
  else `unrouted`'s. One Langfuse client per project, cached. A project with no keys and no
  `unrouted` → `skipped`.

## Trace check

- The 5th item reads Observations API v2 with the keys of the run's use case (from the run
  row; with no run row, from `batch.run`'s `use_case_id`; else `unrouted`).
- Found → `N observations in Langfuse project <project>`.
- Not found there but found in `unrouted` → MISSING `in unrouted, not in <project>`.
- The trace-check service reads the projects env (test host) or local values (laptop, CI).

## Project tool and wrapper

`backend/scripts/langfuse_projects.py` (runs in the backend image as the Compose tool service
`langfuse-projects`, profile `tools`, user root, mounts: the project folder read-write, the
compose folder for the two generated files, the registry from the image):

- `add <use_case_id> --keys-file <path>` → reads `LANGFUSE_PUBLIC_KEY=` and
  `LANGFUSE_SECRET_KEY=` from the file; **checks them**: `GET /api/public/projects` with those
  keys must return one project whose `name` is `<use_case_id>`; writes the project file (600);
  regenerates; deletes the keys file; prints names only.
- `add unrouted --from-langfuse-env /opt/langfuse/langfuse.env` → takes the
  `LANGFUSE_INIT_PROJECT_*` keys (the project must be named `unrouted` by then).
- `regenerate` → validates all project files and rewrites the routes file and the projects env.
- `list` → use case, key prefix (8 characters), file date. Never a full key.
- Exit 0 ok; 1 a check failed (nothing written); 2 usage.

`deploy/compose/add-langfuse-project.sh` runs it with `docker compose … --profile tools run
--rm -T langfuse-projects …` and prints the restart command:
`docker compose -f compose.yaml -f compose.testhost.yaml up -d --force-recreate collector backend`.

## Tests

| Test | Covers |
|---|---|
| `test_langfuse_projects.py` (unit) | env slug; collisions refused; file rules; routes file content and order (3 conditions, `unrouted` default); projects env; key lookup with and without `LANGFUSE_PROJECTS` |
| `test_langfuse_projects_tool.py` | `add` with a fake Langfuse (`http.server`): right project → written; wrong project name → refused, nothing written; `regenerate`; `list` prints no full key; the keys file is deleted |
| `test_batch_runs_tracing.py` | the server span carries `use_case_id` and `run_id` for a stored run, and none for a 401 |
| `test_langfuse_scores.py`, `test_batch_evaluator.py` | scores use the run's project keys; fallback to `unrouted`; `skipped` with no keys |
| `test_check_trace_script.py` | the 5th item uses the run's project; "in unrouted, not in X" |
| `test_compose_files.py` | two `--config` flags; tool service; env files on the test host |
| **CI `collector-routing`** | Collector 0.161.0 with the generated routes (file exporters instead of Langfuse): spans with the resource label, with only the span label, with only `service.name`, and with none land in the right file; config validates |
| CI `langfuse-smoke` | 5 of 5 through the per-use-case lookup (local: `rtr-fraud-validation` is the init project; `unrouted` uses the same keys) |

## Test host switch

1. Langfuse UI: rename the project `model-monitor` to `unrouted`.
2. Create the project `rtr-fraud-validation` and its API keys; save them to a keys file on the VM.
3. `add-langfuse-project.sh unrouted --from-langfuse-env /opt/langfuse/langfuse.env`, then
   `add-langfuse-project.sh rtr-fraud-validation --keys-file <path>`.
4. New backend image; copy the compose files and the Collector config; restart Collector and backend.
5. The next RTR run: trace check 5 of 5, in project `rtr-fraud-validation`.
